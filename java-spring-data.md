# Програма навчальної дисципліни

## «Технології взаємодії серверного додатку з БД на Java (Spring Data, JPA, Hibernate, Liquibase)»

---

## 1. Загальна інформація

| Параметр | Значення |
|---|---|
| Назва дисципліни | Технології взаємодії серверного додатку з базою даних на Java |
| Технологічний стек | Java 17, Spring Boot, Spring Data JPA, Hibernate, Liquibase, PostgreSQL |
| Рівень аудиторії | Студенти, які володіють Java; базові знання SQL/реляційних БД даються з нуля |
| Форми занять | Лекції, групові заняття, практичні заняття |
| Тривалість кожного заняття | 2 академічні години |
| Загальний обсяг | 12 годин (6 занять × 2 год) |

### Передумови (що студент має знати до початку)
- Основи Java (класи, інтерфейси, generics, колекції, винятки).
- Основи Maven/Gradle та структури Spring Boot-проєкту.
- Базове розуміння клієнт-серверної архітектури.

> **Примітка щодо SQL.** Оскільки аудиторія слабко володіє SQL, у кожну тему вбудовано короткий «SQL-місток»: перед кожною новою ORM-можливістю показуємо, у який саме SQL вона транслюється (через `show-sql` / лог Hibernate).

## 2. Мета та завдання дисципліни

**Мета** — сформувати у студентів практичні навички проєктування рівня доступу до даних (DAL) серверного Java-застосунку з використанням Spring Data JPA та Hibernate, а також керування схемою БД через Liquibase.

**Завдання:**
- навчити відображати об'єктну модель на реляційну схему (ORM-мапінг);
- навчити писати запити засобами Spring Data (derived queries, JPQL, `@Query`, Specifications);
- сформувати розуміння життєвого циклу сутності, транзакцій та стратегій завантаження;
- навчити версіонувати схему БД через Liquibase;
- сформувати вміння діагностувати типові проблеми продуктивності (N+1, зайві запити).

## 4. Зміст занять

### Модуль 1. Основи доступу до даних та ORM

---

#### Лекція 1.1 — Реляційні БД, JDBC та ORM: від SQL до Spring Data JPA (2 год)

**Мета:** сформувати понятійну базу та пояснити, яке місце JPA/Hibernate/Spring Data посідають у стеку.

**План за підтемами (90 хв):**

| Хв | Підтема | Деталі |
|---|---|---|
| 0–5 | Вступ, цілі дисципліни | Що навчимося робити за курс; де це в реальних проєктах |
| 5–25 | **SQL-місток: реляційна модель** | Таблиці, рядки, стовпці, типи даних; первинний і зовнішній ключ; зв'язок 1:1/1:N/N:M на пальцях |
| 25–40 | Базовий SQL | `SELECT / INSERT / UPDATE / DELETE`, `WHERE`, `ORDER BY`, простий `JOIN` — мінімум для розуміння ORM |
| 40–55 | JDBC та його біль | `Connection`/`Statement`/`ResultSet`, boilerplate, ручний мапінг, керування з'єднаннями — чому це незручно |
| 55–70 | Що таке ORM | Object-relational impedance mismatch; ідея відображення об'єкт ↔ рядок; плюси й ціна ORM |
| 70–85 | Ієрархія технологій стеку | **JPA** (специфікація) → **Hibernate** (реалізація) → **Spring Data JPA** (надбудова над репозиторіями) → **Liquibase** (версіонування схеми): хто за що відповідає |
| 85–90 | Архітектура застосунку + підсумок | Controller → Service → Repository → DB; що буде на наступному занятті |

**Результат:** студент розуміє, навіщо потрібен кожен шар і як вони пов'язані.

---

#### Групове заняття 1.3 — Налаштування проєкту, перша сутність, аналіз SQL (2 год)

**Формат:** спільна робота під керівництвом викладача; усі виконують однакові кроки синхронно.

**План за підтемами (90 хв):**

| Хв | Підтема | Деталі |
|---|---|---|
| 0–10 | Створення проєкту | Spring Initializr; залежності `Spring Data JPA`, `PostgreSQL Driver`, `Lombok`; структура згенерованого проєкту |
| 10–25 | Підняття БД у Docker | `docker-compose.yml` з PostgreSQL; порти, volume, змінні середовища; перевірка підключення |
| 25–40 | Конфігурація `application.yml` | `spring.datasource`, `jpa.hibernate.ddl-auto` (create/update), `show-sql`, `format_sql`, діалект |
| 40–60 | Перша `@Entity` | `@Entity`, `@Table`, `@Id`, `@GeneratedValue` (стратегії), `@Column` (nullable, length, unique) |
| 60–75 | **SQL-місток: анотація → SQL** | Вмикаємо лог Hibernate; дивимось згенерований `CREATE TABLE` та `INSERT`; пов'язуємо кожну анотацію з рядком SQL |
| 75–85 | Типові помилки конфігурації | Невірний діалект, конфлікт `ddl-auto`, помилка з'єднання; як читати стектрейс |
| 85–90 | Підсумок, Q&A | Чекліст «проєкт працює» перед практичним |

**Результат:** працюючий проєкт, перша таблиця створюється автоматично, студент бачить відповідність «анотація → SQL».

---

#### Практичне заняття 1.3 — CRUD через Spring Data репозиторії (2 год)

**Формат:** самостійне виконання за завданням, викладач консультує.

**План за підтемами (90 хв):**

| Хв | Підтема | Деталі |
|---|---|---|
| 0–15 | `JpaRepository<T, ID>` | Що дає «безкоштовно»: `save`, `findById`, `findAll`, `deleteById`, `count`, `existsById`; ієрархія `CrudRepository`/`JpaRepository` |
| 15–30 | Шар Service | `@Service` поверх репозиторію; навіщо не звертатись із контролера напряму до БД; `@Transactional` на запис |
| 30–50 | REST-контролер | `@RestController`, `@GetMapping`/`@PostMapping`/`@PutMapping`/`@DeleteMapping`; `@RequestBody`, `@PathVariable`; коди відповідей |
| 50–60 | Обробка «не знайдено» | `Optional`, `orElseThrow`, базовий `@ExceptionHandler` → `404` |
| 60–75 | Перевірка через HTTP-клієнт | Postman / `curl` / `.http`-файли; прогін усіх 5 операцій і звірка з таблицею в БД |
| 75–90 | **Самостійне завдання** (нижче) | Викладач консультує індивідуально |

**Завдання для самостійного виконання:**
> Реалізувати повний CRUD для сутності `Product` (поля: `id`, `name`, `price`, `quantity`) з REST-ендпоінтами, шаром Service та перевіркою результатів у БД.

**Результат:** студент самостійно реалізує повний цикл CRUD через Spring Data.

### Модуль 2. Звʼязки, запити та керування схемою

---

#### Лекція 2.1 — Асоціації, життєвий цикл сутності, транзакції та завантаження (2 год)

**Мета:** пояснити складніші механізми Hibernate, що визначають коректність і продуктивність.

**План за підтемами (90 хв):**

| Хв | Підтема | Деталі |
|---|---|---|
| 0–5 | Повторення | Де ми зупинились: одна сутність, CRUD; сьогодні — зв'язки між сутностями |
| 5–25 | Асоціації між сутностями | `@OneToOne`, `@ManyToOne`, `@OneToMany`, `@ManyToMany`; власник зв'язку, `mappedBy`, `@JoinColumn` |
| 25–35 | **SQL-місток: асоціації → схема** | Як анотації перетворюються на зовнішні ключі та проміжні таблиці; які JOIN-и за цим стоять |
| 35–50 | Життєвий цикл сутності | Persistence Context; стани `transient / managed / detached / removed`; що таке «перший рівень кешу» |
| 50–60 | Dirty checking | Як Hibernate сам «бачить» зміни managed-сутності й генерує `UPDATE` без явного `save` |
| 60–70 | Стратегії завантаження | `EAGER` vs `LAZY`; проксі; `LazyInitializationException` — чому виникає і де |
| 70–82 | Транзакції | `@Transactional`, межі транзакції, `readOnly`, поширення (propagation) коротко; типові помилки |
| 82–90 | Каскади + підсумок | `CascadeType`, `orphanRemoval`; підводка до теми запитів (наступне заняття) |

**Результат:** студент розуміє, що відбувається «під капотом» при збереженні та читанні повʼязаних даних.

---

#### Групове заняття 2.2 — Запити у Spring Data (2 год)

**Формат:** спільна робота під керівництвом викладача.

**План за підтемами (90 хв):**

| Хв | Підтема | Деталі |
|---|---|---|
| 0–20 | Derived query methods | Правила іменування: `findByName`, `findByPriceGreaterThan`, `findByNameContainingIgnoreCase`, `And`/`Or`, `OrderBy`, `Top`/`First` |
| 20–30 | **SQL-місток: метод → SQL** | Дивимось у лог, який SQL генерує кожен derived-метод; межі підходу |
| 30–45 | JPQL проти SQL | Запити по сутностях, а не по таблицях; синтаксис, навігація по асоціаціях |
| 45–60 | Анотація `@Query` | JPQL та нативний SQL (`nativeQuery = true`); іменовані (`:param`) та позиційні (`?1`) параметри; `@Modifying` |
| 60–70 | Проєкції | DTO-проєкції (конструктор) та інтерфейсні проєкції; навіщо не тягнути всю сутність |
| 70–82 | Пагінація та сортування | `Pageable`, `PageRequest`, `Page` vs `Slice`, `Sort`; що в SQL додає `LIMIT`/`OFFSET` |
| 82–90 | Огляд Specifications/Criteria API | Коли потрібні динамічні фільтри; загальна ідея без глибокого занурення |

**Результат:** студент уміє обрати відповідний спосіб запиту під задачу та розуміє, який SQL за ним стоїть.

---

#### Практичне заняття 2.3 — Liquibase та вирішення проблеми N+1 (2 год)

**Формат:** самостійне виконання за завданням, викладач консультує.

**План за підтемами (90 хв):**

| Хв | Підтема | Деталі |
|---|---|---|
| 0–10 | Навіщо версіонувати схему | Проблеми `ddl-auto=update` у реальних проєктах; міграції як код у git |
| 10–20 | Підключення Liquibase | Залежність; `spring.liquibase`; `db.changelog-master.yaml`; службові таблиці `DATABASECHANGELOG(LOCK)` |
| 20–40 | ChangeSets | Створення таблиць, додавання колонок, обмежень, індексів; обов'язкові `id`/`author`; порядок застосування |
| 40–50 | Rollback та узгодження з JPA | `rollback`-секції; вимикаємо автогенерацію DDL (`ddl-auto=validate`), щоб джерелом істини був Liquibase |
| 50–65 | **Діагностика N+1** | Відтворюємо N+1 на `Order → OrderItems`; рахуємо запити в логах; чому LAZY-колекція «вибухає» |
| 65–80 | Способи вирішення N+1 | `JOIN FETCH`, `@EntityGraph`, batch-fetching (`@BatchSize`); порівняння кількості запитів до/після |
| 80–90 | **Самостійне завдання** (нижче) | Викладач консультує; підсумок курсу |

**Завдання для самостійного виконання:**
> 1. Перенести схему проєкту з `ddl-auto` на Liquibase (щонайменше 2 changeSets).
> 2. Відтворити N+1 на звʼязку `Order → OrderItems` і усунути його через `@EntityGraph` або `JOIN FETCH`, підтвердивши зменшення кількості запитів у логах.

**Результат:** студент керує схемою через Liquibase та вміє діагностувати й усувати N+1.
