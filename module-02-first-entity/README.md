# Module 02 — Групове 1.3: Перша сутність `@Entity`

Час від SQL та теорії перейти до робочого коду. Створимо справжній **Spring Boot** проєкт
і першу сутність — `Product`. Запустимо застосунок, і **Hibernate сам згенерує `CREATE TABLE`**.
Головне завдання модуля — порядково звірити **кожну Java-анотацію з рядком SQL**.

## Що навчимося
- Розуміти структуру Spring Boot проєкту та його залежності.
- Налаштовувати підключення до бази в `application.yml`.
- Описувати сутність анотаціями JPA: `@Entity`, `@Table`, `@Id`, `@GeneratedValue`, `@Column`.
- **Читати згенерований `CREATE TABLE`** і пов'язувати його з анотаціями (SQL-місток).

## Передумови
- Пройдені [module-00](../module-00-setup/) (встановлено JDK 17, Docker, IntelliJ)
  та [module-01](../module-01-rdb-jdbc-orm/) (розуміння зʼєднання/транзакції/ролі ORM).

## 1. Структура проєкту

```
module-02-first-entity/
├─ pom.xml                                   залежності та версії (через Spring Boot parent)
├─ docker-compose.yml                        база PostgreSQL
└─ src/main/
   ├─ java/com/shop/
   │  ├─ ShopApplication.java                точка входу (main)
   │  └─ product/
   │     └─ Product.java                     перша @Entity
   └─ resources/
      └─ application.yml                      налаштування підключення та логів
```

Код групуємо **за фічами** (тека `product/`), а не за шарами. Коли в модулі 05 з'являться
нові сутності, кожна матиме свою теку — так простіше орієнтуватися.

### Залежності (`pom.xml`)
- `spring-boot-starter-data-jpa` — Spring Data JPA + Hibernate.
- `postgresql` — драйвер бази.
- `lombok` — прибирає рутину (getter/setter/конструктори).

Версії окремих бібліотек **не вказуємо** — їх задає `spring-boot-starter-parent`.
Це головний запобіжник проти несумісних версій.

## 2. Налаштування `application.yml`

Ключові параметри (повний файл — у `src/main/resources/application.yml`):

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/shop
    username: shop
    password: shop
  jpa:
    hibernate:
      ddl-auto: create          # перестворювати таблиці під @Entity при кожному старті
    show-sql: true
    properties:
      hibernate:
        format_sql: true
logging:
  level:
    org.hibernate.SQL: DEBUG
    org.hibernate.orm.jdbc.bind: TRACE
```

Що означає кожен ключ:

| Ключ | Призначення |
|---|---|
| `datasource.url/username/password` | куди й під ким підключатися (збігається з docker-compose) |
| `ddl-auto: create` | Hibernate **перестворює** таблиці під сутності при кожному старті |
| `show-sql` + `format_sql` | друкувати SQL у консоль, читабельно |
| `org.hibernate.SQL=DEBUG` | показувати текст запитів |
| `org.hibernate.orm.jdbc.bind=TRACE` | показувати значення параметрів замість `?` |

> **`ddl-auto: create`** зручний на старті: база завжди «чиста» під поточні сутності.
> Але він **стирає дані** при кожному запуску й непридатний для продакшну. У
> [module-06](../module-06-liquibase-nplus1/) замінимо його на Liquibase.

## 3. Перша сутність `Product`

Файл `src/main/java/com/shop/product/Product.java`:

```java
@Entity                               // клас = сутність JPA (рядок таблиці)
@Table(name = "products")             // назва таблиці
@Getter @Setter @NoArgsConstructor    // Lombok: getter/setter + конструктор без аргументів
public class Product {

    @Id                                           // первинний ключ
    @GeneratedValue(strategy = GenerationType.IDENTITY)  // база сама проставляє id
    private Long id;

    @Column(nullable = false, length = 255)
    private String name;

    @Column(nullable = false, precision = 12, scale = 2)   // гроші -> BigDecimal
    private BigDecimal price;

    @Column(nullable = false)
    private Integer quantity;
}
```

Навмисно **без** звʼязку з категорією — щоб перша таблиця була максимально простою.
Поле `category_id` додамо в модулі 05.

> `@NoArgsConstructor` обов'язковий: JPA створює обʼєкти сутностей через конструктор
> без аргументів. `BigDecimal` для `price` — бо для грошей `double` дає похибки.

## 4. Запуск

```bash
docker compose up -d       # 1. підняти базу
mvn spring-boot:run        # 2. запустити застосунок
```

Застосунок стартує, Hibernate підключається до бази й створює таблицю. У консолі зʼявиться
згенерований SQL. Зупинити застосунок — `Ctrl+C`.

Перевірити таблицю в базі:

```bash
docker compose exec db psql -U shop -d shop -c "\d products"
```

## 5. SQL-місток: анотація → `CREATE TABLE`

Це серце модуля. Ось що Hibernate надрукує в консолі під час старту
(завдяки `ddl-auto: create`):

```sql
create table products (
    id bigint generated by default as identity,
    name varchar(255) not null,
    price numeric(12,2) not null,
    quantity integer not null,
    primary key (id)
)
```

Звіряємо **кожен рядок із анотацією**:

| Java-анотація | Рядок у `CREATE TABLE` | Пояснення |
|---|---|---|
| `@Table(name = "products")` | `create table products (...)` | назва таблиці |
| `@Id` + `@GeneratedValue(IDENTITY)` | `id bigint generated ... as identity`, `primary key (id)` | первинний ключ з автонумерацією |
| `@Column(nullable = false, length = 255)` на `name` | `name varchar(255) not null` | тип і обмеження |
| `@Column(precision = 12, scale = 2)` на `price` | `price numeric(12,2) not null` | грошовий тип |
| `@Column(nullable = false)` на `quantity` | `quantity integer not null` | `Integer` → `integer` |

Порівняйте це з файлом `01-create-tables.sql` із [module-01](../module-01-rdb-jdbc-orm/):
таблицю `products` ми там писали руками — тепер її згенерувала JPA з анотацій.
**Той самий результат, лише джерело різне.**

## Типові помилки

| Повідомлення | Причина | Як виправити |
|---|---|---|
| `Connection refused` / `Connection to localhost:5432 refused` | База не запущена | `docker compose up -d`, перевірити `docker ps` |
| `password authentication failed for user "shop"` | Невірні логін/пароль | Звірити `application.yml` з `docker-compose.yml` |
| `port is already allocated` (5432) | Порт зайнятий | Зупинити стару базу або змінити порт у `docker-compose.yml` |
| Застосунок падає з довгим стектрейсом | Шукайте рядок `Caused by:` | Саме він містить справжню причину — читайте його, а не весь текст |
| `release version 17 not supported` | Обрано не ту JDK | IntelliJ: **Project Structure → Project SDK → 17** |

> **Як читати стектрейс.** Spring виводить довгу «простирадло» помилок. Головне правило:
> шукайте найнижчий `Caused by:` — там першопричина (наприклад, `Connection refused`).

## Завдання для самостійного виконання

1. Запустіть застосунок і знайдіть у консолі блок `create table products`.
   Звіртеся з таблицею SQL-містка вище.
2. Додайте на поле `name` ще обмеження `unique = true`:
   `@Column(nullable = false, length = 255, unique = true)`. Перезапустіть застосунок
   і знайдіть, **як змінився** згенерований DDL (з'явиться обмеження унікальності).
3. Поясніть, чому `price` оголошено як `BigDecimal`, а не `double`.
